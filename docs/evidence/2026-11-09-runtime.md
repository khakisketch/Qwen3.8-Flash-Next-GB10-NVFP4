## Recovery evidence

The host supervisor was killed with SIGKILL while the container was running.
The in-container watchdog logged `host supervisor heartbeat missing/stale;
killing server`; systemd's `ExecStopPost` cleanup removed only the exact
name/label container; `Restart=on-failure` started a new run and the model was
ready in 336 s. A prior attempt hit systemd's start limit because several
manual restarts had consumed the budget; the limit is now 5 starts per 900 s,
and `systemctl --user reset-failed` is documented for maintenance.
